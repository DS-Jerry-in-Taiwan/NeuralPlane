# AGENTS.md

- The actual git repo/config project is `./.opencode/`; run git, CI, and script commands from there, not from the parent `NeuralPlane/` directory.
- `intro.md` in the parent is product/MVP prose. Executable sources of truth are under `.opencode/` (`setup.sh`, `mcp.sh`, `opencode.json.template`, `tests/`, `.github/workflows/`).
- Never commit generated secret-bearing config: `.opencode/opencode.json` and parent `opencode.json` are generated by `setup.sh`, contain API keys, are chmod `600`, and are gitignored.
- Setup/verification entrypoints: `cd .opencode && ./setup.sh --mode native` (default) or `./setup.sh --mode omo`; restart the OpenCode session after any mode switch.
- `setup.sh` reads keys from prompts, environment, or `.env`: `SUPERMEMORY_API_KEY`, `TAVILY_API_KEY`, `BRAVE_API_KEY`, `GITHUB_PERSONAL_ACCESS_TOKEN`, plus optional `MCP_SERVER_PATH` (default `/home/ubuntu/mcp_server/servers/src`).
- `setup.sh` writes `.opencode/opencode.json`, creates parent `opencode.json -> .opencode/opencode.json`, and installs runtime npm deps in `.opencode/.opencode-runtime/`.
- Validation command matching CI: `cd .opencode && bash tests/validate_setup.sh`; CI also runs `shellcheck -S style setup.sh mcp.sh` and basic checks for `.env.example` and workflow YAML structure.
- `tests/validate_setup.sh` exercises all setup scenarios; there is no documented single-scenario CLI flag, so use the whole script unless you edit it intentionally.
- MCP management: `cd .opencode && ./mcp.sh status|start|stop|restart` only manages Docker containers `playwright-mcp-server` and `brave-search-shared`; filesystem/sequentialthinking/git MCPs are OpenCode-managed, and supermemory/tavily are remote.
- Native mode means `default_agent: agent-architect` with housekeeping only; workflow is `agent-architect -> agent-developer -> agent-qa -> HITL/agent-releaser`.
- OmO mode means `default_agent: Atlas - Plan Executor` with housekeeping + `oh-my-openagent`; do not mix OmO runners with native agents, and restart OpenCode before judging agent availability.
- `.opencode/.gitignore` ignores `docs/` and `AGENTS.md`; when tasks ask for those files, verify them by direct file reads, not by `git status` alone.
- Release/deploy/branch-promotion work belongs to `agent-releaser`; require human approval before push/merge/tag/release/prod deploy.
